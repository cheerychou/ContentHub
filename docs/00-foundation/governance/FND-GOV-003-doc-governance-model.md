# 文档治理模式：全保留 · 小索引 · 单一权威

> 本文档借鉴成熟工程实践（docs-as-code、Diátaxis、ADR、SPOT），为 ContectHub 定义一套**从出生即分流**的文档治理立场，避免项目文档随增长而膨胀、重复、冲突。

## 1. 背景：文档为什么需要治理

开发过程中文档作为资产有价值（审计、回溯、知识沉淀、AI 后续工作输入），但**档案收藏**与**快速查询**是两个互相冲突的职责：

- **档案馆**要求全量：过程资产照常产生、照常保留，成本近零。
- **查询入口**要求小而权威：找得到、找得快、找到的**可信**。

把二者混在一层，必然相互拖累。治理的立场是：**不限制产出，治理查询面**——让每份文档"出生即分流"。

## 2. 三原则

1. **全保留**：过程资产的价值在可追溯，git 历史与 `docs/archive/` 是零维护成本档案馆；归档即保留，永不删除。
2. **小索引**：导航、索引、门禁只覆盖"现行有效"文档；归档物理存在但不进导航、不进索引、不进门禁。
3. **单一权威（SPOT）**：同一事实只允许一个权威出处，其余**引用链接，禁止复制**——复制必然漂移，链接不会。

> **权威级联（冲突裁决）**：代码 > active 文档 > 归档文档。文档与实现不符时标记 `deprecated` 或加"性质声明"，而非迁就文档改代码。

## 3. 分层模型

| 层 | 定位 | 内容例如 | 检索待遇 | 生命周期 |
|----|------|---------|---------|---------|
| **制品层** | 现行规范/设计/接口的唯一权威出处 | 本编号体系、文档模板、现行架构/PRD | 进导航 + 索引 + 门禁 | GOV-002 全程管理 |
| **决策层** | 不可变的决策记录（ADR，一句话） | 一条决策一篇，只追加不改写，用取代链表达演进 | 可进索引 | 永不修改，仅被新决策取代 |
| **过程层** | 原始过程资产 | 讨论纪要、分析报告、审计、一次性方案 | **不进导航与索引**，靠 `git log --grep` 反查 | 产出即归档 |

## 4. 分流三问（写新文档前必答）

每新建一份文档时先回答：

1. 描述的是**当前事实**还是**过程中的思考**？
   - 当前事实 → 制品层（挂导航、进索引）
   - 过程思考 → 结果即归档至 `docs/archive/`，不进导航与索引
2. 是否**已有可挂靠的权威文档**？
   - 有 → 写成链接或补充小节，而非新建文档（SPOT）
3. 结论是否**可蒸馏进 KNW 经验教训册**？
   - 可 → 结论入 KNW，原文归档

## 5. 落地动作

| 优先级 | 动作 | 说明 |
|--------|------|------|
| P0 | **产出即分流**：把 §4 三问作为默认动作，写进文档模板与 CLAUDE.md 前置检查 | 把归档从"事后治理"变"出生时默认" |
| P0 | **检索分层**：docs/README 只挂入口/制品类文档，门禁范围与导航一致 | 过程层退出查询面 |
| P1 | **健康指标**：制品层占比、`updated_at` 超期比例，阶段复盘 | 增长异常时触发分层审查 |
| P2 | **ADR**：重要架构/技术决策记录进决策层（保留追加） | 冲突治理制度化 |
| P2 | **新鲜度**：门禁对制品层 `updated_at` 超期发提醒（可选，未来） | 防文档不知不觉过期 |
