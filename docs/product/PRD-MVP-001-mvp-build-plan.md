# 数字内容供应链系统（A-DCSC）MVP 建设方案

> **文档状态**：v2.0，2026-09-04 产品定位头脑风暴定稿后整体重写。v1.x 的 OpenMetadata/Neo4j 企业级方案已废弃，废弃理由见 §9 与 [KNW-EXP-001](../knowledge/KNW-EXP-001-content-supply-chain-lessons.md)。
> **定位依据**：见 [STR-BV-001 §8 产品定位](../strategy/STR-BV-001-digital-content-supply-chain-vision.md)。

## 1. 定位与背景

ContentHub（A-DCSC）是**面向 B2B 企业的内容供应链系统**：让企业以"一份源资产 + 一套配方"的方式，管理从选题研究到多平台发布的内容全链路——单人可用、团队可扩展、生态可对接。

**第一个用户是自有场景**：车地带数字化门店产品（CDD3）运营方的内容营销。现状证据（2026-09 实地盘点）：

- 选题策划（24 期）→ 公众号草稿（44 篇）→ 定稿发表（14 篇）的流水线真实在转，但 5 月后约 20 篇成稿无定稿归宿；同一主题存在 4 份手工副本（含口播稿）。
- 封面图靠 Keynote 手工排版 + 截图，为公众号/抖音/视频号/B站四平台逐一调整尺寸、字号、换行。
- 内容经公众号、官网（chedidai.com/articles）、抖音、微信视频号、bilibili 五个渠道分发，登记分散无追踪。
- 选题提示词、写作提示词（v2.2）已是成熟资产，本质是手工形态的"配方"。

## 3. 核心概念模型

### 3.1 三态分离的内容域映射

| 区域 | 三态 | 实例 | 管理重点 |
|------|------|------|----------|
| **源料区**（原子态） | 不可再生的底片 | 信源链接、行业数据、采访素材、录制原始素材、选题矩阵 | 唯一性、可检索、信源可信度 |
| **母版区**（编辑态） | 黄金母版 | 定稿文章、成片视频——同一主题的**唯一权威版本** | 版本、状态机（创作中→定稿）、消除多副本 |
| **发布态**（派生物） | 配方驱动的产物 | 公众号版/官网版/GEO 变体/口播稿/四平台封面 | 配方血缘、平台元数据、发布状态 |

### 3.2 配方库

配方 = 可复用的生成指令资产：提示词（选题、写作、口播稿改编、GEO 视角画像）、封面排版模板（HTML/CSS + 尺寸规格）。母版 × 配方 → 派生物，生成时自动记录血缘（"这篇口播稿由哪个母版、哪条配方、哪次生成产出"），用关系表实现，不需要图数据库。

### 3.3 关键原则

- **母版是唯一事实源**：发布态可丢失、可重生成；副本没有存在意义，状态只有一个出处。
- **AI 生成可复现**：源料区存风格锚点资产（参考图 + 模型 + 参数），生成记录绑定配方，失败可重生成。概率模型的微差无法消除，"同配方 + 锚点"把差异压到可接受。
- **单人零负担、协作可扩展**：单人模式下流程尽量薄，但 created_by/审核等协作原语从第一天就在数据模型里（M2 启用 UI）。

## 4. 渠道 × 形态矩阵

| 母版形态 | 派生物（发布态） | 生成方式 | 自动化定位 |
|----------|------------------|----------|-----------|
| 定稿文章 | 公众号版 / 官网版 / GEO 多视角变体 | 配方 = 提示词（视角画像 + 关键词侧重） | 高——文本管线是已验证的 AI 强项 |
| 母版视频 | 抖音 / 视频号 / B站 版（导出规格 + 文案 + 标签） | 登记式（自动上传受平台资质壁垒阻断，见 KNW-EXP-001 L-003） | 登记 + 一键跳转，不做自动上传 |
| 封面原图 + 标题 | 公众号 / 抖音 / 视频号 / B站 四规格封面 | **排版渲染引擎**：HTML/CSS 模板 + 无头浏览器截图，替代 Keynote 手工 | 高且确定——规则渲染，非概率生成；文字换行由模板排版约束处理 |

剪辑环节不自动化：成片继续在剪映人工完成，ContentHub 负责母版归档 + 多平台导出规格 + 发布登记（衔接而非替代，理由见 KNW-EXP-001 L-001/L-002）。文生视频作为未来配方类型预留，MVP 不预建。

**M2 视频段交付物（2026-09-04 定）**：口播稿配方生成的下游增加 **配音 MP3（edge-tts）+ 标准 SRT 字幕（断句按 L-001 独立步骤实现）+ 素材清单**，用户在剪映手动导入装配。"生成剪映草稿"方案经调研后关闭——剪映 6.0+ 加密草稿文件，社区草稿协议路线仅兼容 ≤5.9（见 KNW-EXP-001 L-007）。

## 5. MVP 范围

### M0 资产底座

- 三区存储（对象存储 + PostgreSQL 元数据），资产状态机：选题 → 创作中 → 定稿 → 发布中 → 已发布
- 全文检索；既有内容库批量导入（含 Obsidian 目录结构映射）
- 单人模式，无角色 UI，数据模型带 created_by / 审核字段

### M1 配方派生引擎

- **封面排版渲染**：模板库（含四平台规格预设）+ 无头浏览器截图，四尺寸一次渲染
- **文本变体生成**：口播稿 / GEO 视角变体 / 平台适配版，配方 = 入库提示词
- **发布登记**：VidFlow 式登记 + 一键跳转平台上传页 + 平台元数据（链接、发布时间、数据回流字段预留）

### M2 生态对接

- CDD3 营销中心内容包导出（对接其 MK-005 Phase 3 总部下发语义，仅数据模型兼容性预研在 M1 期间完成，不写对接代码）
- 协作原语启用：角色 / 审核流 / 任务分配

## 6. 交付形态与技术选型

**交付形态：API 优先的 Web 应用（前后端分离），docker-compose 自托管起步，浏览器使用。**

选型依据（详见定位讨论与 KNW-EXP-001 L-005）：M2 团队协作、CDD3 API 对接、独立 SaaS 产品化三个未来全部指向 Web 形态；桌面应用路线已被 VidFlow 验证过其迁移成本（Tauri sidecar 重打包、单机天花板）。云端迁移是部署动作而非重构。

| 组件 | 选型 | 说明 |
|------|------|------|
| 后端 | FastAPI + PostgreSQL | 与 CDD3 同构（Django/DRF 亦可，团队熟 FastAPI 则优先） |
| 对象存储 | MinIO（本地卷） | 大视频文件局域网上传，速度非瓶颈 |
| 前端 | React + TypeScript | 与 CDD3 同构 |
| 封面渲染 | HTML/CSS 模板 + Playwright 无头截图 | 规则渲染，确定性强 |
| 文本变体 | LLM API（配方调用） | 复用既有提示词资产 |
| 后台任务 | FastAPI BackgroundTasks | 单人规模够用；规模上来再引入队列 |

**明确移除**（v1.x 方案）：OpenMetadata、Neo4j、Celery。理由：企业级元数据/图谱栈面向多人协作、海量资产场景，与第一阶段单人自用错配；血缘在配方生成关系中已结构化表达，关系表足够。

## 7. 红线（明确不做）

- 不做自动上传发布（平台资质壁垒 + 封号风险）
- 不做自动视频剪辑（VidFlow 已验证创意决策自动化不达预期）
- 不做通用网盘、协同办公套件
- 不做第三方 CMS/CRM 替代品（沿用 CDD3 侧既有红线）
- MVP 不做多租户

## 8. 风险与未决问题

| 风险/未决 | 应对 |
|-----------|------|
| 图片风格一致性只能"可复现"不能"保证" | 风格锚点 + 参数记录，管理预期 |
| 视频成片依赖剪映人工导出 | 定位为衔接；若未来做字幕辅助，断句必须独立于剪切边界（KNW-EXP-001 L-001） |
| GEO 变体效果无法直接度量 | 先做"生成 + 登记"闭环，效果归因留待有回流数据后 |
| CDD3 对接时机 | M1 验证通过前不动 CDD3，仅做数据模型兼容预研 |

## 9. 与 v1.x 的关系（废弃说明）

v1.x（2026-09-03）以"三态存储 + OpenMetadata/Neo4j 血缘图谱"为核心，定位为通用企业 DAM。2026-09-04 定位头脑风暴基于实地证据（自有内容库盘点、CDD3 MK-005 差距分析、VidFlow 复盘）确认：首要痛点是重复加工劳动（配方派生），而非企业级图谱；企业栈与单人起步场景错配。v2.0 整体重写，v1.x 内容可经 git 历史追溯。
