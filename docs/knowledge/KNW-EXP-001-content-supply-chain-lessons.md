# 内容生产自动化经验册（VidFlow 等项目蒸馏）

> 来源：VidFlow（视频自动化创作，2026-07 搁置）项目复盘 + ContentHub 产品定位调研（2026-09-04）。为 ContentHub 的自动化边界决策提供依据，详见 [PRD-MVP-001 §4/§7](../product/PRD-MVP-001-mvp-build-plan.md)。

## L-001 字幕自动化的分条边界不能绑定剪辑剪切边界

| 项 | 内容 |
|----|------|
| 日期 | 2026-07（VidFlow renderer），2026-09-04 蒸馏 |
| 现象 | 自动成片的字幕是"整段一行的字墙"，不可读 |
| 根因 | 字幕分条以 EDL 剪切边界为准（遇被 cut 的词才输出一条），两个 cut 之间全部文字拼成一条无换行字幕；全代码库无任何每行字数/标点断句逻辑 |
| 解决方案 | 改用剪映人工剪辑；ContentHub 定位为衔接 |
| 预防措施 | 字幕断句必须是独立的 NLP/规则步骤（字数上限 + 标点 + 停顿检测），永远不要把"剪辑切在哪"当作"字幕断在哪" |

## L-002 LLM 创意决策在进入管线前必须用真实素材验证

| 项 | 内容 |
|----|------|
| 日期 | 2026-07（VidFlow PoC），2026-09-04 蒸馏 |
| 现象 | PoC 实测 DeepSeek/GLM 两家模型的剪辑决策全部 keep（cut=0），81.8 秒视频零剪切 |
| 根因 | 测试素材脚本与转录不匹配时模型倾向保守；"LLM 剪辑决策质量"是 PoC 报告中唯一未充分验证项，但管线照常建设，直到最后也未闭环 |
| 解决方案 | 项目搁置；成片转人工 |
| 预防措施 | 概率模型的创意决策（剪辑/取舍/风格）属于高风险环节，未在真实素材上达到可用指标前不得进入主管线；规则性环节（转码/缩放/排版）与概率性环节分开设计，前者先自动化 |

## L-003 多平台自动发布受资质壁垒阻断，登记式是正解

| 项 | 内容 |
|----|------|
| 日期 | 2026-07（VidFlow DEV-SYS-007），2026-09-04 蒸馏 |
| 现象 | 抖音需企业资质 + 对公验证（约 10 工作日）；B站不收个人开发者；视频号/小红书无官方发布 API |
| 根因 | 平台侧准入策略，非技术问题；第三方"一键分发"走 Cookie 模拟有封号与 ToS 风险 |
| 解决方案 | 登记式：LLM 生成各平台文案 + 一键跳转上传页 + 剪贴板复制 + 本地状态追踪（pending/done/skipped） |
| 预防措施 | ContentHub 发布态一律登记式；除非平台官方开放 API 且资质齐备，不做自动上传 |

## L-004 纯文生图做不了封面文字排版，需模板引擎叠加

| 项 | 内容 |
|----|------|
| 日期 | 2026-07（VidFlow DEV-SYS-006），2026-09-04 蒸馏 |
| 现象 | CogView 直出封面，文字渲染不准；多尺寸需整图重生成，不可控 |
| 根因 | 文生图对文字排版是概率生成，像素级规格（公众号/抖音/视频号/B站封面尺寸各异）无法保证 |
| 解决方案 | ContentHub 方案：AI 生成封面底图（母版）+ HTML/CSS 模板排版标题文字 + 无头浏览器按规格截图，四尺寸一次渲染 |
| 预防措施 | 含精确文字/规格的图像产物走"模板排版渲染"，文生图只负责无文字的底图素材 |

## L-005 桌面应用形态锁死协作与集成上限

| 项 | 内容 |
|----|------|
| 日期 | 2026-07（VidFlow 工程期），2026-09-04 蒸馏 |
| 现象 | Tauri + Python sidecar 架构：后端每次改动必须重打包 sidecar；macOS 单平台；单人单机天花板 |
| 根因 | 本地存储与多人共享根本冲突；桌面端与云端 API 生态集成成本高 |
| 解决方案 | ContentHub 选 API 优先 Web 应用、docker-compose 自托管起步 |
| 预防措施 | 产品 roadmap 里有多人协作或生态对接的可能时，从第一天选 Web 形态；桌面只做锦上添花的壳（如托盘/快传），不做数据主权层 |

## L-006 境外 API 在 Python 进程中可能被 TLS 指纹掐断

| 项 | 内容 |
|----|------|
| 日期 | 2026-07（VidFlow PoC 联调），2026-09-04 蒸馏 |
| 现象 | curl 可通、Python 不通（JA3 指纹差异），ElevenLabs Scribe 因此弃用，降级本地 faster-whisper |
| 根因 | 出口环境对 Python TLS 栈的针对性拦截 |
| 解决方案 | 跨国上传先本地抽音轨（234MB→0.7MB）；依赖境外服务时提前做 Python 进程连通性验证而非只测 curl |
| 预防措施 | 选型评审时区分"curl 可达"与"运行时可通"；关键能力优先评估国内可用替代或本地模型 |

## L-007 剪映 6.0+ 加密草稿文件，"生成剪映工程"路线对新版用户封死

| 项 | 内容 |
|----|------|
| 日期 | 2026-09-04（jianying-editor-skill 调研，用户剪映实装 11.4） |
| 现象 | 社区草稿协议路线（pyJianYingDraft / jianying-editor-skill，★2942 MIT）仅完美兼容剪映专业版 ≤5.9；剪映 6.0 起加密草稿核心文件 draft_content.json，6.x/11.x 无法正常打开脚本生成的旧格式草稿 |
| 根因 | 草稿协议是逆向工程，官方在 6.0 起对草稿文件加密；依赖第三方逆向协议即依赖剪映版本冻结 |
| 解决方案 | ContentHub M2 视频段交付物定为 **配音 MP3（edge-tts，国内可达，避开 L-006）+ 标准 SRT 字幕（断句按 L-001 独立步骤做）+ 素材清单**——剪映任何版本原生支持导入 SRT，零协议依赖；"生成剪映草稿"方案关闭（用户 2026-09-04 拍板） |
| 预防措施 | 依赖逆向协议/私有格式的集成，选型前必须查当前主流版本是否仍兼容；把"目标应用的大版本升级"当作这类集成的固有风险登记，而不是试验时才发现 |
